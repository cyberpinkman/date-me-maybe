# 双向邀约与图片保存

本轮功能已随 v0.4.0 于 2026-10-05 发布生产，发布记录以 README 为准。

## 两种邀请方式

| 模式 | 谁提议安排 | 谁敲定 |
| --- | --- | --- |
| 我来安排 | 发起人创建时填写 | 受邀人直接接受单项安排，或从范围内选定 |
| 想听 TA 的 | 受邀人在原有收邀情境中填写 | 发起人接受单项安排，或从范围内选定 |

时间按完整的日期与时刻成对提供，最多三个候选；地点最多三个候选；活动最多六项，各活动保留自己的具体偏好范围。单项与范围通过候选数量表达，不另设相互冲突的开关。每次最终约定包含一个时间、一个地点、一个活动，以及该活动选定的具体偏好；没有指定具体偏好时可以留空。

`mode: "host"` 用于发起人安排，`mode: "open"` 用于受邀人安排。新范围增加 `timeOptions` 与 `placeOptions`，并保留 `activities` 与 `preferences.details`。原有单值 `date/time/place/activity/preferences.detail` 表示选定的结果。所有候选都只有一个时可预选，但预选不是对方的确认。

范围归属由服务端保存的模式推导。只有另一方可以完成范围内选择，且范围作者必须已同意当前版本；日期和时间不能从两个候选中拼接。改动已经敲定的时间或地点，会清除对方旧批准，需要重新确认。所有更新继续经过已有的归属检查、事务行锁、版本检查和幂等日志。

历史 `fixed/flexible` 记录及没有时间、地点候选数组的 v0.3 邀请保留原有语义。新字段保存于现有 JSONB，不新增数据表。产生新范围记录后，服务端不可直接退回不认识 `host` 和候选字段的 v0.3.1；回滚或修复版本必须继续保留这些记录的读取与回应能力。

新增或修改候选时间时，所提供的候选必须全部在未来；最终选择和确认时检查实际选中的时间。历史范围中未选中的过期候选不会阻断另一项仍在未来的安排。验证在事务内、共享模型转换之后执行，失败不会写入状态或幂等响应；已成功的相同请求重放仍返回原响应。

## 受邀人转为发起人

“我也要发起邀约”只出现在受邀人已完成回应的结果卡下方，不放在七步收邀过程或导出的卡片中。入口完整导航到创建页，建立新的草稿，避免原邀请链接的受邀身份继续控制接口。用户可先写邀请，准备发出时再登录；不会自动创建账户、发送邀请或把原发起人的身份复制进新邀请。

## 手机图片保存

浏览器不提供统一的网页相册授权或直接写入手机相册接口。本功能展示真实图片元素并保留原生长按菜单，在浏览器支持文件分享时提供系统分享按钮；不模拟相册授权弹窗，也不把“打开分享菜单”当作“已保存到相册”。

图片预先编码为 JPEG 文件，用户点击分享时直接调用系统分享，避免异步生成图片耗掉浏览器要求的短时用户激活。只分享图片本身，不附带发起人管理地址或受邀链接。系统分享不可用、用户取消或分享失败时，预览和打开大图、下载图片仍可用。

原生长按菜单的名称、保存到照片的选项以及微信内的行为由实际手机与浏览器决定。桌面或模拟手机视口只能验证页面与图片，不能代替真机相册保存验收。

实现参考：[Web Share 的用户激活与文件分享要求](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)、[文件分享能力检测](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/canShare)、[原生长按菜单样式](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/-webkit-touch-callout)。

## 本地验证

2026-10-05，Node.js 22.22.3：68 项单元/边界测试及 18 项真实 PostgreSQL 集成测试通过。之后调整未完成选择时的按钮禁用状态，11 项前端合同测试再次通过。桌面及 Chrome 手机视口分别完成双模式的实际选择与确认，另验证单项直接接受、改期重新确认、旧记录显示，以及受邀人从结果页进入新草稿并在登录后继续。

图片预览正常解码、窄屏无横向溢出。真实手机相册及微信原生菜单尚未验收；工具限制了 Blob 大图进一步检查。本轮本地验收后已发布生产，发布时复用了有效登录会话，未重新向真实邮箱发信。

正式部署另用两条测试记录走完 host 与 open 模式，由独立匿名浏览器回应并核对发起人结果。独立 API 读取确认所有候选及各活动偏好仍在，最终四项安排与双方批准版本正确；旧 v0.3.1 多偏好记录仍正常显示。生产图片预览为 900×1129，正常解码；回应后进入新草稿的入口已实测。
