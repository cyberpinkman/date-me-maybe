# 运营管理后台

v0.6.0 已于 2026-10-05 发布，正式入口为 [admin.opendater.com](https://admin.opendater.com)。本轮已验证正式域名、数据库迁移、真实邮箱验证码登录与数据加载。具体核对范围见本文末尾及 [README 发布状态](../README.md#发布状态)。

后台用于查看账号、邀约和日程使用情况，首版提供概览、7/30/90 天趋势、邀约转化漏斗、可搜索分页的用户与邀约列表，以及用户详情。业务数据接口全部只读；当前不提供用户修改、批量删除、导出或访客埋点。匿名访问者没有可靠的账户身份，因此不会展示推算出来的匿名用户数、DAU 或打开率。

## 本地启用

在[基础后端配置](backend.md#本地数据库和配置)上，额外配置两个服务端变量：

```dotenv
APP_ORIGIN=http://127.0.0.1:3010
ADMIN_ORIGIN=http://localhost:3010
ADMIN_EMAILS=admin@example.test
DEV_MAILBOX=1
```

使用相同本地服务和端口、不同主机名，可同时验收独立入口与仅限当前主机的 cookie。打开 `http://127.0.0.1:3010` 访问邀请工具，打开 `http://localhost:3010` 访问运营后台。两项 `ADMIN_*` 必须同时填写；同时留空则关闭后台 API。Origin 只包含协议、主机和端口，不带路径或结尾斜杠；生产必须使用 HTTPS。

`ADMIN_EMAILS` 为逗号分隔的精确邮箱许可名单，服务端统一去掉首尾空格、转为小写并去重。真实运营邮箱只保存在部署平台环境变量中，不写进公开仓库、前端脚本或静态页面。更改名单并部署新配置后，数据接口会按新名单重新验证当前登录者。

```bash
npm run db:migrate
npm start
```

本地使用示例邮箱申请后台登录码，然后从本地 `/api/dev/mailbox` 读取最新验证码。这个入口只在本地回环测试环境启用；`*.test` 邮箱不会收到外部邮件。实际生产后台使用 Resend 投递验证码，配置 `RESEND_API_KEY` 和已验证的 `EMAIL_FROM`，并关闭 `DEV_MAILBOX`。

## 独立认证与权限

后台复用现有用户身份表，但不复用前台的登录挑战或会话：

- 后台登录只允许邮箱验证码，路径为 `/api/admin/auth`；前台仍使用 `/api/auth`。
- `004_admin_auth.sql` 创建 `admin_verification` 和 `admin_session`。前台验证码不能用于后台登录，前台会话也不能替代后台会话。
- 后台使用独立的 `opendater-admin` cookie 前缀，cookie 仅属于当前主机；签名密钥通过固定后台用途从 `AUTH_SECRET` 派生。生产 cookie 使用 Secure、HttpOnly 和 SameSite=Lax。
- 登录发码及验证均检查邮箱许可名单。每个数据请求还会重新检查有效后台会话、已验证邮箱和当前许可名单，不能靠隐藏页面按钮获得权限。
- `/api/admin/*` 仅在配置的后台主机接受请求；主站访问这些路径返回 404。写入类登录请求还要求匹配后台 Origin，不接受跨站请求。
- 后台只开放发码、验证码登录和退出所需的认证端点，不开放账号设置或 Google 登录。数据接口只有 GET；认证、限流等安全记录仍正常写入。

退出会撤销后台会话，前台登录状态保持独立。管理员在后台看到的用户邮箱只来自通过授权的数据接口；公共 HTML 只是页面结构，不包含用户记录或许可名单。

## API 与数据口径

| 接口 | 内容 |
| --- | --- |
| `GET /api/admin/session` | 当前后台登录身份，未登录返回 `user: null` |
| `GET /api/admin/overview` | 汇总、按上海日期统计的趋势、创建批次转化漏斗 |
| `GET /api/admin/users` | 用户搜索、筛选及分页 |
| `GET /api/admin/users/:id` | 账号摘要与发起/主动绑定的邀约 |
| `GET /api/admin/invitations` | 邀约搜索、模式/状态筛选及分页 |

详细字段、查询限制及指标定义见[运营数据契约](admin-data-contract.md)。需要区分：

- 当前“已确认”与“曾经确认”：改期后的邀约可能正在等待重新确认，漏斗仍保留先前成功确认的记录。
- 总预约数与参与者数：待赴约安排按邀约去重，同一个约定绑定两个账号仍只算一份。
- 已绑定受邀用户与绑定次数：用户数按账号去重；用户详情中的绑定邀约数才按邀请计数。
- 趋势记录的是注册和创建；一份邀请被创建不等于已发送或已打开。漏斗按所选时间内创建的邀约计算，不是该时间内发生的全部回应动作。

后台不返回完整邀请语、私人偏好、地点、具体见面时刻、空闲时间窗口或忙碌原因，也不返回分享链接、令牌、验证码、IP 和会话记录。账号未主动绑定的匿名邀约，不会按昵称或邮箱相似性归属到该账号。

## 构建与域名路由

同一个 Express/Vercel 项目提供主站和后台，无需复制业务数据库。构建输出为：

| 产物 | 用途 |
| --- | --- |
| `dist/index.html` | 本地 Express 主站 |
| `dist/admin.html` | 本地 Express 后台 |
| `public/app.html` | Vercel 主站静态文档 |
| `public/admin.html` | Vercel 后台静态文档 |

不再生成 `public/index.html`，构建会移除旧文件。这样默认静态首页不会抢先覆盖按主机名选择页面的规则。`vercel.json` 先将 `admin.opendater.com/` 重写到 `/admin.html`，再将普通 `/` 和 `/i/:token` 重写到 `/app.html`。本地 Express 根据配置的后台 Host 选择首页。已有邀请链接和微信根目录验证文件继续使用原路径。

后台响应带 `noindex, nofollow, noarchive`，敏感 API 使用 `Cache-Control: no-store`。禁止索引和前端路由都不能替代服务器认证；即便获取公开的后台 HTML，也无法直接读取业务数据。

## 发布与验收

1. 在现有 Vercel 项目添加 `admin.opendater.com`，按平台返回的目标配置对应 DNS 记录，确认 HTTPS 证书已可用。不要改动主站或 Resend 已有解析。
2. 在 Production 设置 `ADMIN_ORIGIN=https://admin.opendater.com`，把实际许可邮箱写入服务端 `ADMIN_EMAILS`；不需要新增前端邮箱配置。
3. 运行现有生产构建迁移流程。`004_admin_auth.sql` 是新增认证隔离表，不重写业务邀约，也不改变 v0.5.0 日程规则；不能修改已经应用的 001–003 迁移。
4. 按项目发布流程构建并切换域名。若部署尚未使用正式后台 Host，只能核对构建和公共静态页面，不能据此认定 Host 限制或真实后台登录已通过。
5. 在正式后台验证实际邮件收码、登录、概览/趋势、筛选/分页和退出；确认非许可邮箱、未登录请求以及前台会话都无法读取后台数据。同时复查主站登录、已有邀请链接、健康检查、`www` 跳转和微信验证文件。

本地真实 PostgreSQL 集成测试覆盖数据口径、上海日期边界、共享模型状态一致性、只读响应范围及独立认证权限。上线结果须另外记录，不能将本地通过等同于生产已验证。
