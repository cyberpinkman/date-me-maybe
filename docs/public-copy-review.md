# 公开页面文案审查

审查日期：2026-10-04。范围是当前待上线版本的用户界面；本次未发布生产站点。

## 审查范围

- 浏览器标题、搜索摘要与页面初始加载。
- 创建邀请的三个步骤：昵称和心意、时间活动地点、送出前检查。
- 登录入口、Google 登录、邮箱验证码、重新发送、登录异常。
- 邀请准备完成页、专属链接、复制提示、我的邀约、空列表。
- 收邀的七个情境、逃跑按钮、返回、时间与氛围选择、活动分支、小约定。
- 等回应、等确认、地点待定、已经约好等状态；更新安排弹窗。
- 约定卡图片、保存与复制提示。
- 邀请找不到、网络异常、回应接收中断、安排更新冲突、未知异常。

## 已完成的修改

| 位置 | 修改前 | 修改后或处理原则 |
| --- | --- | --- |
| 页面标题与摘要 | 暧昧期邀约原型、手机端交互原型 | 见一面 · Date Me Maybe；摘要介绍写下心意、选时间、期待见面 |
| 昵称与文案提示 | 上面是示例昵称和文案 | 换上你们的昵称，再写一句只有 TA 能懂的话 |
| 邀请确认步骤 | 逐步选择时间、氛围和具体偏好，最后确认 | TA 选好安排后，回来一起说好这次见面 |
| 创建按钮 | 生成这份邀请 | 把邀请准备好 |
| 分享入口 | 打开收邀页 | 打开这份邀请 |
| 待确认标签 | 等发起人确认、等接收者确认 | 根据正在查看的人显示“等你说好”或“等 TA 说好” |
| 发起人回应页 | 双方确认同一个安排，才会生成正式约定 | 把时间和地点一起说好，就等见面啦 |
| 发起人页底部 | 所有状态都提示 TA 回应后这里会更新 | 分别说明等回应、等自己说好、已约好等当下情境 |
| 修改安排 | 原来的确认不会沿用 | 换了时间或地点，再和 TA 说好一次 |
| 安排冲突 | 打开最新版本 | 安排刚刚有更新，已经帮你换成新的了 |
| 约定卡 | 双方已确认 | 我们说好了 |
| 登录不可用 | 登录服务正在准备中 | 暂时还不能登录，先把心意写好，稍后再来 |
| 认证错误 | 可能直接显示英文供应商错误 | 按明确错误代码显示验证码不对、过期、尝试过多、邮箱填写、限流等中文提示；未知错误用自然中文说明 |
| 未预期错误 | 直接显示异常原文 | 只展示已标记为用户可见的文案；其余显示“刚才没能完成，稍后再试试吧” |

保留了“装作不在意，其实很期待”“今天的开心，有点超标”等暧昧表达。未增加拒绝选项，也未改变逃跑互动和收邀步骤。日期、地点、验证码等必要填写说明继续保留。

真实邮件已使用“见一面 · 你的登录验证码”主题和“见一面”发件人，通过用户收件与登录验收；当前本地服务已关闭测试邮件箱，登录页不再显示其说明，测试邮件箱接口返回 404。

服务端对外报错也已同步校对：不再向页面显示 JSON、接口、字段、提交标识或版本等工程措辞，改为检查填写内容、刷新安排或重新打开页面。HTTP 状态与错误代码保持原样供程序处理。修改后构建、现有单元测试和真实 PostgreSQL 集成测试均通过。

## 生产上线前仍需核对

1. 正式配置关闭本地测试邮件箱。测试邮件箱的说明仅出现在明确的本地验收界面，不应在公开站点出现。
2. 部署时确认服务端与前端均使用这次校对后的构建，避免新页面仍收到旧服务端的工程提示。
3. 用正式配置重新构建，实际查看创建、登录、我的邀约、收邀七步、等待确认及已约好页面，确认没有旧的缓存文案。
4. 检查真正发出的验证码邮件；若启用 Google，再核对其同意页面中的应用名称、域名和返回页面。邮件及第三方页面不属于本次前端模板修改。
5. 生产部署后检查错误验证码、过期验证码、邀请链接不完整和安排已更新的提示，确保仍为中文产品语言，不出现供应商错误原文。

代码注释、开发文档、接口名称中的工程术语不属于公开页面文案，未为此改动实现命名。低影响文案修改未新增逐字符串测试；构建与已有契约测试由主任务统一执行。
